# ADR-0030：按协议重放新的兑换任务原件

状态：2026-10-28 采纳。实现与验收进度见 STATUS；评分政策沿用 ADR-0029 的 `transaction-agent-evidence-v3`。

## 问题

已有评分器支持同任务共享三维证据，但历史来源入口依赖 MangoSwap 的父报告和特定采样迁移。新对象不能为了使用同一评分规则而复制这些历史槽位。实际多对象调查也表明，Agent 返回的兑换方案可以采用不同路由：0x AllowanceHolder、Hydrex 的包装协议、Kyber MetaAggregationRouter；只检查 HTTP 成功或交易哈希不能证明功能兑现。

## 决定

新增协议解码与原件来源重放入口，复用现有报告、共享任务模型和单值评分计算，不修改维度、30/40/30 权重、UNKNOWN 处理或已发布报告。

- 协议解码按 calldata 结构核输入资产、输出资产、精确金额、收款人和最低到账。对象名称、ID和提供方自报 PASS 不参与判定。未知协议或未支持的执行模式明确保留缺项。
- 解码、部署归属、实时费率、独立模拟和实际执行分别取证。解码通过不产生完整 F 或 B 结论。Kyber 不透明 executor 数据不冒称已全部解码。
- 有多个已知截止时间时取最早值。Hydrex 包装方案的外层截止可能晚于内部 0x 授权期限，不能用外层期限延长内部权限。
- 新来源包直接引用冻结任务、注册证明、实际交付原文和 HTTP/RPC 原件，不依赖 MangoSwap 父报告。重放不信任人工写入的分数、SUMMARY 或 RESULT 布尔。
- ACP 可用性从请求资料和费用均已就绪后计算交付时间。用链上资金就绪、提交事件及规范区块核实际间隔；操作者等待付款或延迟核验不记成 Agent 故障。
- F 将实际方案与原请求匹配，再用同一个固定区块中的完整授权、兑换、余额及余授权模拟核效果。历史有效窗口内的模拟只能说明当时效果，不证明现在仍可成交。
- B 只使用计划中的正常真实履约，绑定交易输入、执行者、目标、交付、回执、事件、收款、资产变化和确认距离。服务费、平台建单、内部资金转入及历史模拟均不能补 B。

每个任务分别支持 A/F/B 的适用判据，维度内按任务与判据去重。首次小额任务的结果是明确范围的观察评分，不宣称统计可靠率或该 Agent 全部能力均已验证。没有实际履约的对象仍缺 B，不为增加覆盖数补满分。首次任务计划和原始失败保留，不更改旧版本样本充分性要求。

## 首批事实与兼容性

先核多个真实对象后实施。TheSafeRouteBot 与 Hydrex 的两份不同协议报价均已用相同效果标准通过独立历史模拟；Hydrex 随后取得新有效报价并完成一笔真实兑换。Tator 付款后的业务 500、过期导致未发送的本地预检均保留，分别按实际归因记录。

现有 MangoSwap 报告和来源重放路径保持。新入口采用独立 origin adapter；正式报告仍通过既有导入、不可修改存储和公开包流程。首份新报告使用已核验的 ERC-8004 身份，不制造链上身份或将 ACP jobId 伪装成注册 tokenId。

本次不新增自动付款或常驻交易 worker，不修改钱包权限，不引入依赖，不部署合约，不发币或铸造身份/报告。公开包仅含已审查的非秘密业务与链上原件；本地签名、登录令牌、付款授权和私钥不进入报告。

## 验证

协议模块的一项组合验收已通过：两个真实协议样本统一意图绑定、错收款/错金额拒绝、内部早截止、未知协议保留；旧工程测试不重复。新来源重放与导入/公开包的必要组合验收待实际执行后记录在 STATUS，不将实现中写为通过。
