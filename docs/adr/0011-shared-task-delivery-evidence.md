# ADR-0011：共用任务履约证据接入

日期：2026-10-18。正式取证及评分前固定。沿用service-contract-v1的三维、30/40/30、10/7/7样本及缺项规则，不覆盖旧政策或报告。

## 选择依据

已采群体中12个Olas身份共享Mech请求/IPFS交付格式，原声明目录有113个工具条目、30种operation名；这只是声明覆盖，不是113种已评分能力。两个完成源原7个行为任务分别覆盖2与4个operation，共4种，适合先验证跨工具履约规则。现有verify_prediction_chain实际只使用交易、事件、历史getter和任务标识，不依赖市场结算或概率结果，直接复用其通用履约逻辑。

两个免费MCP事实查询候选目前没有共同的固定区块查询闭环，且已记录额度或传输缺口。本轮不重复探测，也不把Schema合规升级为功能通过。功能声明一致性仍需实际输入输出及适用独立判据；本轮新增的是交易任务证据。

## 身份与任务规则

- 当前只支持可信配置中的Gnosis普通Mech marketplace履约。注册owner必须为官方桥，桥的service→agent映射、Mech的serviceId/serviceRegistry/getOperator和链上tokenURI真实文档共同绑定同一身份。域名不是执行归属证明，不要求某个提供方的operator域名。任务发生时另核历史service与实际operator，不把当前注册前推为历史注册。
- 使用真实request_id；任务键为链、Mech和request_id的规范组合，与用途、随机槽号无关。每份报告保持用途互斥。已有完成源只继承其原七个behavioral槽，不挪用functional槽或按旧分数重新挑选。
- 新取证先在固定确认区块内发现最多32条公开索引记录，按既有顺序取首七个不同、结构符合普通marketplace请求的任务，保存计划后再读取结果。排除项及原因保留；不足七个保留空槽/UNKNOWN，不按结果换槽、不无限翻页。
- 核验实际请求和交付交易、成功回执、区块实例/确认、事件发出地址及顺序、任务ID、历史执行者/授权、优先窗口、费用类型及上限、调用参数和链上CID。请求与交付文件通过原始CAR/DAG认证；交付requestId及实际工具与本任务/注册工具声明对应。
- 工具声明可来自tokenURI文档所链接manifest的真实GET原件，来源与摘要入包；不把目录自报准确率或旧报告判定当依据。格式、内容归属与业务正确性分开。本维度只证明结果是否被正确归属并完成协议交付，不证明预测准确、收益或其它业务答案正确。

## 编排、复核与兼容

注册/协议发现后自动挂接适用任务，按operation关联功能。未支持、缺资料、平台错误保留UNKNOWN，已证实的履约矛盾为FAIL。后台可信协议静态分支，不允许metadata指定代码/评分器/RPC。

来源完成清单、采样计划、原件与报告只追加。报告生成和数据库导入都从同一份计划、原始HTTP/RPC/CAR复算，不直接接收写入的PASS；未支持任务类型继续拒绝。原有预测信用结果保留原政策，不复制或改名为通用功能分。

复用旧来源不冒称新业务调用；新对象自动取证只读公开历史，不创建Mech任务、付费、签名或写链。两维不足仍无综合分。最小必要验证覆盖两个已有对象的多个工具、一个未配置对象的真实接入，以及错误身份/交付绑定拒绝；已通过的底层规则和网络测试继续复用。
