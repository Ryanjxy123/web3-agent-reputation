# ADR 0012：版本化四态判定与失败归因

日期：2026-10-09。范围：本轮第 2 项。

复用现有 Outcome 和 Reason，不增加状态机、数据库表或网络依赖。新计划使用模板 @2，冻结输入与断言明确规则版本 2；旧 @1 输入默认版本 1，保留既有聚合原因与序列化，历史报告哈希不变。

PASS 必须有充分任务证据；FAIL 必须由合法授权、派发上下文和独立证据支撑。原始脱敏 HTTP envelope 与解析响应、任务 payload、endpoint、时间窗口交叉核对。已证明的 5xx、错误响应结构、显式失败与不支持声明分别保存标准原因；Agent 返回的平台故障字符串不能替代平台观测。写入失败使用 canonical 回执判定，损坏 RPC 材料不能产生业务 FAIL。

UNKNOWN 保留授权、限流、超时、网络、RPC、未确认和证据不一致等原因。无响应无法证明服务自身故障。非法 JSON 在安全出口被拒绝时无法保存可靠脱敏响应，保持 UNKNOWN，不凭错误日志判断 Agent 失败。

NOT_APPLICABLE 只用于冻结声明未包含、评审预先明确排除且从未派发的能力。已声明支持而执行失败必须进入 FAIL 或 UNKNOWN。排除依据、任务状态、原因、HTTP 和 RPC 原始材料全部进入既有 Evidence Bundle，供后续复核使用。

读写仍共用 Task、Worker 和纯规则。报告保留 M1 PARTIAL 与原 policy-v1 门槛；本轮不增加完整三维评分。真实异常测试、纯规则边界测试和阶段 Review 的实测结果见 STATUS。
