# ADR-0028：已核新功能纳入正式多能力评价

日期：2026-10-27。状态：采用。新政策`transaction-agent-evidence-v2`，结构`shared-task-assessment-v2`。

用户要求将真实新任务纳入正式评价。ADR-0027的独立快照保留为历史来源，新报告复用其原件重放，而不抄快照中的PASS。ADR-0026的三维、30/40/30、能力/声明/案例等权与未知区间原则保持；v1报告及算法不变。

正式范围包括即时兑换、定时订单管理和限价订单管理。原生币与不同入口属于即时兑换的声明/案例，不额外算一个等权功能。管理任务的正常目标是创建、合约查询、本人撤销和退款，完成它不等于成交；自动执行、周期、价格触发、最佳价格与免gas仍未选。只按规范身份、协议和来源配置接入，不按Agent名称或预期分数分支。

v1要求每项功能的A都有可判响应，阻止已核F/B进入综合结果。v2只修订这一点：每个已选功能仍须安排明确A案例，未实际观测的响应保留未采，不生成请求或耗时；对应案例区间为[0,100]，按原能力等权进入A范围。整个Agent范围的A仍须至少有一个有效、明确可判的业务响应，否则A和综合分为空。旧API的响应只支持旧API案例，不成为V4响应证明。

F仍要求每项已选功能有可判声明核验，B仍要求各正常履约案例达到原先目标；不借此次修订放松交易核验。缺业务证据、测量无效和平台错误不统一归责Agent。每案例以P/V/U计算[100P/(P+V+U),100(P+U)/(P+V+U)]；未采也属于结果未决范围。先按案例/声明/能力聚合，再按30/40/30求综合上下界，不取中点或把未知当精确0/100。

新增功能会改变评价范围和能力权重，未知也可能扩大区间。新旧分数不能直接解读为提供方性能改善或恶化；不预设新分必须上升。沿用旧样本的时间和task_id，新增三笔只增加三个独立任务，同任务的多项判据不增加任务数。

新政策只采用结构v2，原政策只采用结构v1；读取时按结构选择对应纯规则。新增静态来源适配重放原31任务、三笔链上任务及双来源manifest，核身份与所有字节绑定，追加新声明配置/报告/证据包，不修改旧catalog、ADR、快照或报告。三维分由core计算，平台和前端不得手填。

迁移只追加新报告，无数据库表迁移。先更新权威类型，再生成Schema/OpenAPI/TS；验收一项组合用例覆盖未采A区间/全A无证据阻断、F/B门槛、旧v1不变，以及真实34任务/篡改拒绝。复用之前已通过的交易核验与退款实验，不再签名、付费、广播或联网重采。
