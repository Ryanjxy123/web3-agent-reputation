# ADR-0006：本机平台、报告持久化与后台任务

日期：2026-10-18。状态：已实施并完成本机功能验收；浏览器视觉验收 BLOCKED，详见 STATUS 与 LOCAL_PLATFORM。

## 决定

首个真实闭环完成后，用已有纯规则和报告实现本机网站。沿用 Vue 3 / TypeScript / Vite、FastAPI / Pydantic 2、PostgreSQL；一个仓库，API 和 worker 两种进程，不引入微服务、通用插件执行框架或旧数据库。

浏览入口展示真实已发布报告和缺资料候选。接入入口接受完整注册标识或已支持注册页链接，直接入队；普通用户不选择政策、填写 RPC 或确认启动。标识解析不请求用户 URL。未适配或缺资料结果保留，不虚构分数；平台处理失败与 Agent 业务失败分开。

AgentSummary、AgentDetail、ReportSummary、EvaluationSubmission、EvaluationJob 先在 core 定义，再生成 Schema 与 TS；API 的 OpenAPI 从实际路由生成。报告分数继续由 core 从证据样本计算，API 不接受直接评分。

PostgreSQL 保存候选、只追加的已发布报告和可变的任务状态。同一注册标识同时最多一个活动任务。worker 用数据库租约和递增 fencing token 领取、续租和发布；每次更新都核对持有者、token 与有效租约。过时进程不能覆盖新任务或发布报告。报告导入核对原始清单、文件摘要及重新派生的分数，数据库拒绝对已发布报告的更新和删除。

同一内部对象 key 一旦取得完整规范注册身份，就不能被其他完整身份覆盖。旧短资料线索可补齐为首次规范身份，等价写法可归一化；冲突候选或报告导入在同一事务中拒绝。该规则由原子 upsert 条件实现，避免并发首次导入相互覆盖。兼容现有五候选和两份报告，无迁移；只新增这条身份冲突的定向真实 PG 回归，不重跑此前集成用例。

首个后台接入配置由运营端选择已验证资料，不从前端接受执行命令。新的按需评价重新采集可用性，复用未变的历史交易和声明原件，明确历史窗口；不把读出旧报告当成新测评。评价需要的公开只读开关和代理属于运营配置，默认关闭；用户本轮已授权的免费范围由本机 worker 显式启用。没有付费 Agent、签名或链上写入。

本机 PG 使用本项目独立 runtime 数据目录、随机密码与回环端口，不改变旧服务。凭证文件忽略且不输出。证据下载只允许已发布报告实际引用并校验过的公共文件，不开放任意文件路径；原始文件以附件返回。

## 兼容性与验证

首次建立本项目数据库，没有旧数据迁移、清库或 SQLite 回退。历史评分政策与已生成报告保持不变。新的应用契约属于增量类型，统一生成；新依赖先核对官方版本并在独立环境验证，再锁到 uv / pnpm 文件。

必要验证为真实 PostgreSQL 的导入与只追加约束、并发领取与过时租约拒绝、一次 API 正常/无资料流程，以及前端类型检查和构建。按需评价的实际采样另记为产品业务。此前通过的纯规则和凭证测试继续复用，不为本机页面再跑整套。
