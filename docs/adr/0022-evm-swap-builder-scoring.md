# ADR-0022：可复用 EVM 兑换方案与真实履约评分

日期：2026-10-27。政策版本：`evm-swap-builder-v1`。状态：正式采样前冻结；采样及报告结果另记。本文不表示样本已经完成。

## 范围与角色

评价公开注册服务提供的 ERC20 精确输入兑换方案，以及该方案经用户授权签名后在真实链上兑现的情况。首版协议范围为 Uniswap V3 `exactInputSingle((address,address,uint24,address,uint256,uint256,uint256,uint160))`，可由已核实的智能账户 `executeBatch((address,uint256,bytes)[])` 原子执行精确额度 approve 与 swap；直接调用同一兑换协议的路径也可单独核验。链、资产、decimals、router、factory、收款人、输入金额、滑点和执行账户来自采样前冻结的任务与可信协议配置，不按 Agent 名称、ID 或指定买方写评分分支。

服务提供方构造方案、操作者授权并签名、链上账户执行三个角色分别列明。操作者的签名交易不能冒充提供方自主签名或托管资产。注册链与执行链分别取证；不得为了执行链为 Base 而伪造 Base 注册身份。接口必须有可核验的注册身份及服务来源关联，品牌、同名、同域名线索不能自动拼接不同身份。

本报告只对已测兑换能力给范围分；其他功能声明逐项记录尚未覆盖，不因某项缺失重分配权重，也不把一个身份的多个工具当成多个 Agent。批量账户包装是本次兑换的执行方式，不等于已评价批量支付、任意合约执行、所有路由、价格最优、收益或资金整体安全。

## 冻结采样与用途

公共协议配置为 `configs/swap-task-plan-v1.json`。每批在第一次正式请求前持久化带 CSPRNG 任务 ID 的批次 manifest，按该配置固定 A01–A10、F01–F07、B01–B07 共24槽，并绑定身份、准确服务入口、请求参数、采样顺序、用途和适用协议配置。若后续任务的输入依赖前序实际余额，必须在 manifest 中先冻结确定性的余额分配规则，再在发送前持久化该槽的确切整数参数；不能按已观察分数选择参数或替换失败槽。

- A：十个独立业务请求，连续 A 槽发送间隔至少30秒；不是 health、目录、RPC 或仅付款挑战。计时仅从该任务携付款头的业务 POST 发出到完整业务响应接收，排除先前挑战、签名及操作者 RPC。至少八个可判结论才出分。
- F：七个独立实际业务请求。可以只取得方案并以可信固定块 `eth_call` 验证，无需花费兑换本金。每个任务检查整套功能判据，不把一个方案的多个字段拆成多个样本。
- B：另外七个独立真实兑换任务，保留全部尝试及其关联交易；可按预冻规则往返使用已有资产。每个任务检查完整业务兑现，不把 approve 与 swap 拆成两个任务。

全部三维的 task ID、sample ID 唯一且用途互斥。一次业务的挑战、服务费、返回方案、模拟和执行仍是同一个任务，不能换前缀重复入分母。2026-10-23 可行性 pilot 只作背景，不回填本轮前瞻分母。任何未发送、受阻、缺源或失败槽原位保留，不补抽成功对象，不自动重试未知付款或未知广播。

## 判据

### A：服务可用性

PASS 要求真实业务响应完整可解析，业务状态与约定的方案输出相符；HTTP200、正常402挑战或 RPC 在线均不足以通过。完整可归属服务响应明确违背接口契约，且有归责依据时 FAIL。认证、限流、付款未完成、平台/代理/依赖故障、传输截断和原因不明为 UNKNOWN；已授权付费预期的正常挑战不计失败。保留完整错误原文和归责说明，不把操作者签名兼容性问题算作 Agent 错误。

沿用既有公式：`A = 80 × PASS/(PASS+FAIL) + 20 × latency_ratio`。成功请求 p95 取 nearest-rank；不超过1000ms时 latency_ratio=1，达到10000ms为0，中间线性。十槽全部保留且至少八个确定结果。延迟描述为本次线路下的访问体验，不声称纯服务端耗时。

### F：功能声明一致性

每个确定任务同时核对：

1. 请求与提供方真实返回绑定；执行链、输入/输出 token、独立 decimals 和精确整数金额与冻结请求一致。
2. 实际 calldata 的收款人、输入金额、零原生币转出、固定 router/方法和受支持路由符合请求。若有 approve，spender 为本任务 router 且额度恰为输入金额；不接受无限授权或夹带未知动作。
3. 最低到账量与提供方报价、冻结滑点及确定的整数取整规则一致且大于0；不能只比对展示字段而不检查真实 calldata。
4. 可信固定区块上按真实执行账户模拟完整调用，成功解码实际输出，且输出不少于该最低量。

明确可归属的输入、输出或交易约束矛盾为 FAIL；正确格式本身不等于功能通过。原生 ETH 与 WETH、human amount 与 raw amount 必须区分。展示标签误导作为独立发现列明，主要资产约束以请求和真实 token 地址/decimals 为准。

提供方估值与后来区块模拟不同，不在缺少同一声明区块的情况下直接认定报价错误；不以市场涨跌或利润给分。Router02 该方法没有 deadline 参数，metadata 有效期不自动构成链上到期保证；仅在提供方明确承诺且证据证明违反时判相应 FAIL，否则报告限制。未支持路径、缺模拟、节点不可读或无法归责的回滚为 UNKNOWN。七槽均有确定结论才计分。

### B：交易行为可靠性

每个确定任务核对：提供方原响应及冻结 intent 与真实 transaction/calldata 的完整对应；实际签名操作者/执行账户角色；链号、交易哈希、canonical block/hash/index、回执及至少64块确认距离；完整 approve/swap 调用、目标、金额、收款人及原有授权；官方 factory 对应 pool；同笔真实 Swap 与 ERC20 Transfer 的方向、整数本金及实际到账不少于最低量。不能只凭外层成功、钱包历史或服务费转账判断业务完成。

资产方向及 token0/token1 排序按任务计算，不写死单方向。以同笔事件为主要单笔资产证据，固定块前后余额作交叉核验；同块其它活动须识别，不能无条件把整块变化归因于本笔。服务费、兑换本金、网络费分别列明；网络费只依据实际 receipt/可信协议 oracle，缺失项不当0。操作者自定费用预检预算不解释为提供方承诺或所有链费用的绝对封顶。

完整证据显示可归属任务违反已冻结交易约束或明确虚报完成时 FAIL；缺任务关联、确认、执行证明、未知协议、操作者故障、未发送或无法归责的保护性回滚为 UNKNOWN。不得为产生差异而故意发送危险调用或将正常安全拒绝判失败。七槽均有确定结论才计分。

## 计分、发布与兼容性

F、B 分别为 `100 × PASS/(PASS+FAIL)`，不使用预测概率信用分。保持 A10/F7/B7、F/B各七个确定结论、综合权重30/40/30；任何维度不足均 PARTIAL 且不出总分。UNKNOWN/NOT_APPLICABLE不补0、不降门槛。真实全部通过的子维度可以100，区分由真实延迟、失败或一致性差异产生，不事后改规则制造非满分。

沿用 `EvaluationReport`、`ScoredSample`、`CapabilityCoverage` 和只追加 PostgreSQL 报告。新增政策使用独立来源 verifier，从 manifest 绑定的原始业务请求/响应和可信 RPC 重建结论，不接受 collector 自报 PASS 或手填分数。旧政策与旧报告不重算。公开包只选择必要的冻结任务、无付款头的业务请求、原响应、计时观测、身份/协议来源和 RPC 原件；付款授权签名、交易签名、Privy/P256、owner/keychain、凭证与带密钥 RPC URL 留在私有目录。不能仅把私有目录改名来公开。

必要验证只运行一次新规则离线重放及关键错误收款人、缺回执、来源篡改边界，复用已有权重和互斥验证；真实采样不是工程测试。共享政策枚举按现有生成链更新 Schema/TS/OpenAPI。页面显示固定三维、实际兑换范围、操作者执行角色、代表样本和未覆盖功能，不落入旧历史增仓说明。
