# ADR-0012：按需复评补齐同一冻结任务的缺失原件

日期：2026-10-18。实施及补证前固定；评分规则、样本门槛和权重不变。

## 实际触发

首个未配置对象的真实流程已固定七个任务，六个通过，另一个读取请求文件遇到ConnectError。已有来源若一直被直接复用，之后复评也无法补齐缺项。按需复评应恢复缺失证据，同时保留旧报告与原七槽计划。

本轮两个旧对象原七个行为任务实际分别覆盖2、3种操作，合计4种。ADR-0011选择依据中“2与4”混入了第二对象全十四任务的数量；该文件已被证据摘要引用，保留原字节，此处勘误。该计数不参与评分。

## 决定

- 只有新一次评价可对既有完成的native任务来源补证；来源在本次run内时不自动重试。HTTP客户端仍无自动重试。
- 在发送前保存补证计划及原bundle、完成清单和七槽计划的摘要。身份、快照、任务ID、用途、次序与CID保持原值，不选择新任务替代失败或未知任务。
- 仅补没有取得的交易/输入/输出原件；成功原件直接复用。已认证的坏内容或已确定FAIL不通过重新采集消除。每个缺失请求在本次复评只尝试一次，仍失败则保留缺项，不循环补采。
- 新原件、bundle、完成清单和报告另建目录；旧来源和旧报告不覆盖。生成与导入继续从来源、计划、RPC、交易和CAR原件复算。

这是任务证据的恢复步骤，不增加业务调用、签名、付款或链上写入。复用旧任务的历史时间与本次取证时间分开显示；缺项仍不折成0分、不降低七个确定结论的门槛。必要验证复用本轮已有六项，只对真实连接失败所暴露的补证路径做一次复评。
