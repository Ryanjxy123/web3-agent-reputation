# ADR-0009：通用评价优先，专项评价按条件附加

日期：2026-10-18。状态：执行方向已记录；具体指标、阈值、样本条件和新政策版本须在实施评分前固定，尚未实现。

## 问题

用户指出：日常提交评分不能再次等待逐对象开发，平台可以只评价通用标准覆盖的项目。此前计划将预测正确性、完整业务深度核验与扩充固定名单放在自动接入之前，偏离了普通用户提交后自动评价的要求。

## 决定

普通评价以可复用的通用项目为主；业务专项在已有适用规则和证据时自动附加。适配按接口规范、证据格式和必要业务语义复用，同规范的新对象自动采集与执行，不按对象开发专用代码。

| 维度 | 通用项目的实际含义 | 证据范围 |
| --- | --- | --- |
| 服务可用性 | 声明入口的实际协议响应、合法只读调用的业务成功、延迟和稳定性 | HTTP 与协议/业务结果分开；登记页或历史文件可访问仅支持对应入口结论 |
| 功能声明一致性 | 声明、发现到的实际操作、输入输出及真实调用结果是否一致；适用时用确定性答案交叉核验 | 元数据或 Schema 合规单列，不能替代实际功能验证；只为已测的具体声明给结论 |
| 交易行为可靠性 | 有关联证据的真实任务与执行交易，其执行归属、状态、目标/参数、事件及任务完成是否一致 | 依据共同交易/回执和任务格式核验；只读任务不虚构交易，收款钱包和无关成功回执不作履约证据 |

预测准确率、收益表现、最佳策略、完整投资流程等属于按能力选择的专项，不作为所有对象进入基本评价的统一前置条件。一个 Agent 的多项功能分别匹配通用项及现有专项；普通用户不选择方案、不确认第二次启动。

接入流程为：注册入口 → 自动采集身份和功能资料 → 匹配已支持的协议及通用项目 → 受控执行/读取证据 → 出具报告。MCP、A2A、公开 API 等为优先考察的协议模板，并非声称这些模板已实现或任意操作均可自动调用。

通用项目只能证明所测内容。缺证据的项目显示 UNKNOWN，真正不适用显示 NOT_APPLICABLE；不支持一项仍可展示其他已有证据和部分评价。三维均充分才按既定 30/40/30 出综合分，缺维度不补 0/100、不重新分配权重。已测范围与声明覆盖必须在报告中明确。

## 实施顺序

当前 task 为 `GENERIC_EVALUATION_BASELINE`：先从已有群体资料确定跨对象可复用的项目、适用条件和最小证据，再固定政策并接入自动流程。已有预测名单资格调查降为专项扩展任务；新对象评价不以进入这份名单为条件。

优先交付通用项目与协议匹配、自动采集、部分报告及多功能适用/缺项展示。使用多对象检验同一套流程与规则，继续推进至少 10 个真实公共 Agent 的完整三维评分。已有 567 身份资料与功能映射复用，不重做群体调查。

## 兼容性与验证

ADR-0004/0008、原始证据及已发布的 3 对象/4 报告保持原版本，不把旧专项分改名成通用分。新政策与报告范围分别标识；新增共享字段按既有类型生成链维护。

外网启用、受控 HTTP、可信 RPC、免费只读范围及秘密保护沿用原约束。通用接入不授予签名、付费、主网写入或任意服务探测权限。

本次仅更新方向和文档，工程测试 NOT_RUN；没有改动评分代码、权重、样本门槛或已发布数据。实施时只验证实际变化的关键路径，复用既有有效结果。
