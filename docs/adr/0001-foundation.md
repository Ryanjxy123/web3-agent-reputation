# ADR-0001：基础框架与V1.0规划的工程细化
状态：建议采纳；在用户仓库M0审查后记录实际采纳/调整，不代表负责人已批准一切细节。

保持原需求：凭证查询/核验/存证、三维度、四态、八类受控样本、ERC8004读取、确定性证据、三合约、报告独立复核、M0–M4。

新增或明确：
1. API与worker合为单服务包的不同入口，避免重复；core/verifier独立。原PRD目录是建议，不需为目录强行做微服务。
2. API加`/api/v1`前缀；所有文档/客户端一致。统一DTO生成Schema，禁止前后端自定义两套字段。
3. policy-v1公式和阈值保留，编辑/冻结文件用JSON整数基点；用Fraction计算与精确阈值比较。不是修改原始工程权重。
4. M1小样本只生成partial；到M2才达到20/10/10完整要求。不得降门槛让早期demo看起来满分。
5. 状态分开：run生命周期、slot业务四态、dimension完整度、接入建议、报告完整性、anchor发布状态。已确认关键任务冲突即使partial也可以给“不建议接入”，仍不伪造综合分。
6. B必需声明覆盖用最弱覆盖/最小样本约束，范围外宣称保留；不能跳过未知能力后叫完整。这是对PRD“覆盖”计算的可执行细化。
7. 身份链/执行链/锚定链及local deployment instance分开；EIP712结构为项目自定义双角色绑定，不是ERC8004新增标准字段。
8. SQL租约不能保证外部恰好一次，增加fencing+持久fixture ledger+合约幂等+发送不明reconcile。
9. 独立复核不仅根据自报stats算分，还重放确定性断言并重建槽位统计；在线锚定使用外部信任配置。原始链下请求真实性仍非数学保证。
10. 公网适配从安全出口之后启用；本地闭环不依赖8004scan/key/模型服务。8004scan评分是外部背景，不是我们的真值。
11. Git初始状态未知，不自动init覆盖已有库/改remote。用户为负责人，工作分支经review合入main，远程主分支保持稳定。

代价：多记录几类状态、较严格边界、上游版本管理需要少量工作。收益：后续队友增加协议/模板/策略无需重写主链路；不把缺证据、发布失败或平台故障错判成Agent信用问题。
备选未采纳：微服务/Redis队列/全网爬虫/一开始全A2A/MCP/模型直接打分；理由是额外运维和不确定性不能增强M1核心证明。
