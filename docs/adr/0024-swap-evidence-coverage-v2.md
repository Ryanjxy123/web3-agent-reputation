# ADR-0024：ERC20 兑换方案评价的完整来源合并与证据覆盖门槛

状态：2026-10-27 用户批准；`evm-swap-builder-v2`。在新主批次冻结后才执行其标记的未执行任务。

## 决策

三维及权重保持服务可用性 30%、功能声明一致性 40%、交易行为可靠性 30%。业务判据、真实业务 POST 计时、A 延迟公式、链上核验和 64 区块确认距离均沿用 ADR-0022；ADR-0023 的 ABI 勘误继续适用。v1 的 ADR、配置、冻结批次和已发布报告不修改、不重算冒充 v1 完整报告。

v2 的 A 使用一个完整的 10 槽窗口，至少 8 个确定结果；B 使用一整个 7 槽窗口，7 个均须确定。F 使用主批次在采样前显式绑定的全部功能槽，数量至少 7，没有固定最大次数。每个任务仍是一整个独立业务任务，不将字段拆成样本，不与 A/B 重复使用。F 出分同时要求：

- `decisive = PASS + FAIL >= 7`；
- `5 * decisive >= 4 * planned`，即确定证据覆盖率至少 80%，使用整数比较；
- `planned` 是绑定的全部 F 槽数；UNKNOWN、未执行和 NOT_APPLICABLE 均保留在该覆盖分母中，不默认为失败、不删除。

达到门槛时，F 分数为 `100 * PASS / decisive`。真实 FAIL 必须全部纳入并扣分；证据不足不推定 Agent 失败。未达到门槛时 F 值为空，报告 PARTIAL、无综合分。比如 14 槽中 11 个确定结果不足 80%；12 个确定结果满足覆盖门槛。其余旧政策继续原先的固定槽数和门槛。

## 本次来源与前瞻采样

本次 v2 主批次绑定原批次及其完整维度复评批次这两个来源的真实 SHA-256：A 取最新来源的完整 10 槽，F 按来源顺序合并两个来源的完整 7 槽（合计 14），B 取原来源的完整 7 槽。两个来源已有 FAIL、UNKNOWN 和未执行槽全部保留；不是选择八个已成功结果。F 的评分别名 F01…F14 与 `source_campaign`、`source_slot`、原 request_id/task_key、任务文件及 SHA 一一映射，不改写旧任务或真实 run 目录。

新主批次 `schema_version=swap-campaign-v2`，`aggregation.kind=whole-dimension-source-union-v2`；`aggregation.parents` 按时间排列，含每个来源的路径和 SHA；`availability_source`、`functional_sources`、`behavioral_source` 明确整组选择。首个 v2 批次恰为上述两个来源，且第二个来源须通过 ADR-0023 的父来源校验。未来扩充 F 也必须在新增任务发出前冻结新增完整来源组及其全部槽；不能追加已知成功样本、替换失败、悄悄扩大分母或循环重跑至通过。

`aggregation.pending_request_ids` 冻结本轮允许继续的尚未执行任务。它们的真实业务发送及完整接收时间不得早于新主批次 `created_at`；未执行槽仍为 UNKNOWN。旧槽按各自来源原有冻结时刻核验，不要求历史样本在新政策之后重新发生。所有任务 UUID 在评分分母中全局唯一。身份、执行账户、协议、资产及业务范围必须与来源一致；不将其它注册身份或品牌能力合并评分。

## 兼容、证据与验收

核心共享政策枚举新增 v2，`DimensionScore.planned` 仅在 v2 的 F 维度使用实际绑定槽数；不新增评价维度或更改权重。公开包仍仅导出白名单业务请求正文、业务响应、无签名只读链证据和来源哈希；不包含付款头、付款签名、原始已签交易、登录或私钥材料。平台离线重放必须验证所有来源哈希、完整组选择、槽别名和前瞻时间门槛，不能接受前端传分。

必要验收只在真实补采完成后运行一次：重放真实 v2 报告，验证 11/14 与 12/14 覆盖边界、真实 FAIL 纳入、v1 原规则不变，以及既有错收款人 FAIL、缺回执 UNKNOWN、篡改来源拒绝等关键边界。验收未运行前标 NOT_RUN；完整分数仍由实际证据决定，不由本 ADR 保证。
