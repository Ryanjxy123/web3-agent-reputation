# ADR-0005：完整采样槽位与注册身份绑定

日期：2026-10-18。状态：已实施。补充解释 liquidity-history-v1，不改变 ADR-0004 冻结的范围、样本、阈值或权重。

## 决定

完成采样计划与达到确定样本门槛同时满足，维度才有分。可用性保留全部 10 个槽位，其中至少 8 个有确定结论；中断或缺证据的槽位保留为 UNKNOWN，不能直接删掉。功能与行为各保留 7 个固定任务，各需 7 个确定结论。少交两条可用性记录不能提前得到完整总分。核心和外层采集均执行该规则。

ERC-8004 注册持有人、收款钱包和业务执行钱包是不同角色。Registered 事件核实身份登记，不要求注册者就是执行者，也不从收款钱包推断执行身份。当事件中的 agentURI 是内嵌 JSON 时，可严格解码其中明确的 Operating wallet 与 record 服务地址，用作登记时已发布的执行关联；之后仍逐任务核对记录钱包、真实交易发送者及固定块仓位持有人。

历史功能样本核实增仓后的披露，不能附加“必须恰好三笔交易”的行为组限制。额外兑换或解包记录保留，实际增仓按唯一的公开操作标签定位；本次行为组的三步核验范围保持不变。

## 兼容性与验证

补齐遗漏槽位的核心检查是实施修复；没有删除不利样本或降低门槛。仅更新并运行受影响的 scoring 用例一次，验证 8 条确定可用性记录省略另外 2 槽时不得产生维度分或总分。没有重跑其他已通过测试。JSON Schema 不因这一规则修复改变。

注册内嵌资料、任务和固定状态均保留原始响应、来源与摘要。早期失败采集目录不覆盖；后续只补缺项，已有有效结果直接复用。新增披露、行为与面向用户报告契约统一由 core 类型生成，目前没有数据库迁移或旧 API 兼容层。
