# Query 转账记录 Checker v1

本规则扩展 `service-contract-v1` 的证据来源，不改变 A/F/B 的样本门槛、任务互斥、权重或历史政策。

Checker `query.erc20-transfer-record` / `v1` 判断公开查询返回的一笔交易中，预先指定 ERC20 合约发出的全部标准 Transfer 事件中，转入预定地址的总量是否与服务公布的整数一致。预先指定 token、链、接收地址及正数 half-up 取整；不根据结果挑选事件或放宽容差。独立 RPC 来自操作者固定配置，读取 chain/head、交易、回执、固定交易区块和该区块的 decimals。确认距离至少 64，核对交易/回执/区块/日志归属与唯一位置。

完整确认链证据与公布金额一致为 PASS；失败交易、无目标事件、金额矛盾为 FAIL。网络失败、来源冲突、缺项、确认不足、工具错误、未适配输出为 UNKNOWN。原件丢失、摘要变化、计划/身份/请求/报告与重建值矛盾属于完整性错误，拒绝发布，不能降级为 UNKNOWN。

首个经过源码审阅的协议适配器为 `bobai.activity/v1`：仅认证注册端点 `https://brainonbnb.com/mcp` 的 `bobai_activity({})`；输入 Schema 必须严格为空对象且禁止额外属性。允许一次免费只读调用，不执行响应中的链接、付款建议或代码。适用性基于认证服务、链及真实工具 Schema，不包含 Agent ID 判断。其他提供方需要单独审阅安全边界和输出映射；同名工具或 readOnlyHint 不构成授权。

计划在调用前冻结身份、注册证明、端点、工具、空参数、token、接收地址、费用零、重试零及一次调用限制；证据索引绑定真实初始化、目录、调用和 RPC 原件。历史试验原件可由后建索引关联，但不得把后建索引说成调用前计划。正式发布从原件重建样本及 Checker 元数据。

一个无参数查询只对应一个固定任务键；重复调用不能凑成七个不同任务。此类单样本报告 F/B/综合均保留 null；没有 A 采样时 A 同样为 null。PASS 仅证明该交易的指定 token→预定地址事件与金额，不证明永久销毁、供应变化、最新性、历史完整性、自动化执行或 Agent 行为归属，不产生 B。

本规则与确定性匹配不依赖 LLM；现有模型仅可辅助理解声明，不改变判定、评分或安全范围。
