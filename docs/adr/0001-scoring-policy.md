# ADR-0001：首版评分政策与证据准入

日期：2026-10-18。状态：产品政策已确认；具体指标、阈值和样本条件待实现前设计，本文件不表示评分模块已经可运行。

## 背景

老师要求评价服务可用性、功能声明一致性和交易行为可靠性。用户要求至少 10 个真实公共 Agent 获得完整评分，结果能表达真实差异。平台自动选择适合的方案，不让接入用户选择方案。

## 决定

三项维度分各为 0–100。初版综合分：

`综合分 = 0.30 × 可用性分 + 0.40 × 功能声明一致性分 + 0.30 × 交易行为可靠性分`

功能声明一致性略高，突出实际能力是否兑现声明。三维证据及样本均充分才计算综合分；缺项显示待评价，不补 0、不重分配权重。少样本和范围结论不冒充完整评分。

正式评价前固定指标、阈值、样本条件和政策版本；同类对象用同一标准。适用指标可包括真实成功率、延迟和波动、代表性声明兑现程度，以及可归属交易的执行结果和承诺匹配程度，具体计算方式不在本次访谈中假定已完成。

评分须验证实际区分能力，不能仅凭 HTTP 成功给 100 分。若正式结果缺乏区分，先审查样本与指标是否过于粗糙；不编造错误、不人为扣分、不按本批排名硬分档，也不按预期分数筛选对象。政策修订发布新版本，不覆盖旧报告。

选取对象前检查注册、功能声明、可调用业务、独立判据和可归属交易证据。被查询钱包历史、收款钱包和身份注册成功不能替代 Agent 的履约证据。写任务的完成认定仍须匹配链实例、执行者、目标、事件、任务关联和确认状态等必要信息。

不可测、不可评分与尚未核实分别如实记录缺项及后续动作，保留为扩展目标；仅完整三维评分对象计入至少 10 个验收数量。

## 兼容性与迁移

新项目没有已发布评分，无数据迁移。旧项目分数不导入为新评分，也不按新权重回算冒充新评价。后续实现须记录政策版本和证据来源，报告只追加；重评失败保留历史有效报告，同时展示本次失败状态。

## 后续验证

实现后用一次必要验证覆盖权重计算、缺证据不出综合分及旧版本报告保持不变，再以真实业务证据验收完整链路。本轮仅文档决策，应用测试 `NOT_RUN`；业务可测性尚未验收。
