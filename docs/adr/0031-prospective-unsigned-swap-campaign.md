# ADR-0031：版本化的前瞻兑换采样来源重放

状态：2026-10-28 采纳。适用于新的前瞻采样来源，不改旧报告。实际采样、费用及交付以 STATUS 和原件为准；实现或本地回归通过不等于完成外部实验。

## 决定

新增 `unsigned-swap-evidence-v2` / `retained-unsigned-swap-campaign-v2`，对应 `unsigned-swap-report-origin-v2`。按 schema 与 adapter 双重分派，继续生成既有 `shared-task-assessment-v3` 及 `transaction-agent-evidence-v3` 报告。核心案例→声明组→能力等权、单分 `100P/(P+V)`、30/40/30、正常 B 实证门槛和 UNKNOWN 处理不变，不按对象名称写评分规则。

冻结计划预先确定全部任务、CSPRNG UUID、实际请求、正常执行目标、案例、声明组及判据。新来源的 `campaign_plan` 指向该计划；原始 ACP 请求必须逐字段匹配，真实需求提交不能早于冻结时间。仅准备请求文件的时间不能代替真实提交时间。旧任务显式引用原来源，保持原请求、收款、时间与证据，不伪称前瞻采集。

报告完整保留计划槽位，包括未取得交付、未适配协议及尚无执行原件的任务。没有原件不生成一条假观测，不从已成功任务反推采样分母；任何预定正常 B 案例未齐，仍按核心门槛阻断相应 B/综合分。服务费、建单、授权、模拟或保护退出都不是正常实际兑换。

同一真实任务可以分别提供 A/F/B 原件，按任务＋维度＋判据去重。A 对完整正常业务响应从要求及费用均就绪后计时；边界验证不混入未声明的正常报价 SLA。F 分开核请求、声明字段、默认参数、协议解码、source归属及完整固定块效果；B 独立核真实交易、任务/执行者/目标、原calldata、事件、资产变化、授权清理和原有64块确认距离。确认距离不冒称 finalized。

## 缺省参数、拒绝与来源

真实请求省略的字段保持省略。slippage 只采用已认证接口 schema/default 说明，缺默认定义不臆造数值；taker 未声明默认语义时，实际解码收款人可以记录，但不能因此虚构默认承诺或执行收款归属不明的方案。参数归一化仅是派生核验视图，不修改原请求。

完整拒绝首先绑定公开身份、原要求、实际 ACP job、提供方提交、交付哈希及匹配的链事件。认证拒绝可以说明安全参数验证，但不能冒充完整可用报价。正常已就绪请求收到认证的内部/上游500等错误或不完整交付，A记本次服务交付失败；合法市场/保护拒绝缺归因保持UNKNOWN，错误输入不计正常A。F仍独立判断，不将泛化上游500、无流动性、低滑点保护、平台读取失败或未适配统一扣功能分。拒单判通过需有具体非法参数与明确验证拒绝的证据，不把含糊 error 或没有资产执行视作成功履约。

超时不能只依据操作者等候。可判超时需正额资金事件、原要求已就绪、可信链号及规范固定结束块，并有绑定合约/job/provider且完整覆盖观察区间的空提交事件查询。缺窗口或请求/响应不完整保持 UNKNOWN；缓存聊天不能抹去已独立观测到的提交事件。采用全部有效观察窗的最大截止时刻，不用较短窗口覆盖较长证据。

source 自报标签、ABI selector 或包装协议 origin 不能证明实际聚合器归属。可选 `route_bindings` 将有来源的部署映射与实际内部路由、同模拟块运行代码哈希交叉验证；缺部署来源/代码原件保留 UNKNOWN。五联报价只有在同参数、共同有效固定块和独立净到账效果齐全时才比较已测候选，不声称全市场最优；我们发出的四份指定source请求不能证明自动模式内部确实查询了四源，该声明另保留缺证据。

## 兼容性与迁移

旧 `unsigned-swap-evidence-v1` / `retained-unsigned-swap-v1` / origin-v1 的路径、固定文本、案例与逐字回放保持。新 origin 不冒充旧版本，来源 schema/adapter 不符直接拒绝。新 ADR 作为新包的必要哈希输入；旧包不添加新必需文件或重算旧分。

新真实执行意图使用方向无关的 `pre_input_raw` / `pre_output_raw`；若既有生成器采用其它字段名，来源可显式给出 `execution.pre_balance_fields = {"input": "字段名", "output": "字段名"}`。字段值必须与原固定块模拟中的实际输入/输出地址余额匹配，再与回执块原始 getter 和逐交易事件对账。旧 v1 默认 `pre_usdc_raw` / `pre_weth_raw` 语义保持，不编辑、补写或改哈希输入。

迁移以追加来源/报告实现，不更新旧行、旧原件或已发布摘要。不增加网络/签名 worker、不接受证据指定的任意 RPC、不改变钱包权限、不发币或铸造身份/报告。

## 定向验证

单个离线组合验收覆盖真实旧 Hydrex 原件严格重放及字节保持、缺省参数、安全拒绝与上游错误分离、不完整交付、方向无关余额字段映射与反绑拒绝、预定槽位保留及缺正常 B 阻断。受控字段变体仅为工程负控，不是新增公共样本。完整外部采样与真实数据库/网站交付由实际命令另记；未运行项不写成通过。

## 同一协议内的反向兑换

0x Settler 的首个输入动作既可以是 `TRANSFER_FROM`，也可以是官方 `UNISWAPV3_VIP`。后者在一次动作中拉取 permit 声明的输入并交换 V3 路径；支持空签名的 AllowanceHolder 转发，不把“没有单独TRANSFER_FROM”误判为缺输入。校验唯一首输入、精确 token/amount/nonce、收款到当前 Settler、44字节 hop 的连续资产和最终输出，并继续使用更早的嵌套 deadline。fork/poolId/价格限制是解码事实；没有独立来源时不声称已核池部署。

`BASIC` 的严格ERC20余额比例费用可作用于本任务输入或输出资产，必须destination等于该资产、offset=36、精确transfer ABI和有界ppm；输出费用不能错标为输入费或未适配。最终Settler和包装协议净到账下限仍独立核验。实现不按Agent名或单个池地址分支；旧两份真实报价的完整解码JSON等价性在必要VIP组合回归中一并验证。
