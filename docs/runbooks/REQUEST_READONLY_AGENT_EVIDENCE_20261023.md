## 接收后先检查什么

| 材料 | 最小检查 | 不能据此直接推出 |
| --- | --- | --- |
| 实例身份与功能 | 注册链/表/ID、声明来源与版本；确为不同实例 | 多个钱包/仓位就是多个Agent，注册链就是业务链 |
| 可实测服务 | 方法、参数、实例路由、只读授权、费用/限流；确认可合法重复采A槽 | 只有历史导出或平台健康页就能给Agent A分 |
| 固定窗任务清单 | task/job ID、能力、时间、状态、交易引用；含失败/中断/拒绝/合理不执行 | 只提供成功列表就能认定全任务可靠率 |
| 选中任务原件 | 实际输入/约束、输出/交付、时间/期限、已有报价或固定块引用 | 事后说明、截图或摘要等于原始请求 |
| 执行归属 | 链、执行账户、Agent到账户/委托的关联、业务tx hash | 收款人、owner、relayer或结算交易就是实际执行者 |
| 独立样本 | 各维满足原政策；7F/7B任务不复用，一任务多tx仍只算一任务 | 两个示例已经足够正式出分 |

第一步的两个实例各一个示例只用于判断补源是否可行，不生成新完整分。进一步取样前固定声明范围、时间窗、规则和顺序，不按结果挑成功样本。材料缺项时先记录缺项；若两个实例本来属于不同业务能力，分别评估可复用部分，不把它们硬塞进一个判据。

Zyfai特别需要实例/EOA→Safe映射、策略/任务标识、当时配置与再平衡约束、真实业务交易关联；ZK证明存在时再取对应输入和验证引用，不要求为本研究生成新证明。ACP特别需要provider/client角色、job ID、原始需求/交付，以及**业务执行交易与ACP付款/结算交易分别列明**。

保留提供方的原文件、来源、取得时间和完整性信息，不把历史导出自动当公开发布许可。签名只取已有公开链上引用或已消费/失效的历史材料，不接收仍可用于转移资产的授权。只读凭证按既有本地secret机制保存，不进入仓库、前端、原件包或公开报告。
