# ERC-8004 / 8004scan 接入与复用方案

核对日期：2026-10-02。当前网页资料不是固定接口；执行 live 接入前必须完成版本锁。来源见 `docs/references/SOURCES.md`。

## 1. 先区分三个东西
- ERC-8004 是身份、声誉反馈与验证注册相关的标准提案；官方 EIP 页面此次读取标注 Draft。[S01]
- erc-8004-contracts 是上游合约/ABI/部署资料。读取它，不需要重写其完整注册体系。[S02]
- 8004scan 是既有发现、反馈与指标产品，提供公开开发者 API/OpenAPI。它不仅是网页目录；其已有指标不能包装成本项目原创，也不能当本项目真值标签。[S03][S04]

本项目补充的是**凭证业务的测评执行与证据评价层**：确认有限能力→随机任务挑战→独立业务事件断言→缺失与充分度处理→带固定规则的报告复核。
ERC-8004 本身已有 Validation Registry 设计，不能宣称“它完全没有验证机制”。本项目是具体场景下的执行器、规则与报告实现，不替代其标准。

## 2. 复用矩阵
| 已有内容 | 具体用法 | 禁止做法 |
|---|---|---|
| Identity Registry、ERC-721 owner/tokenURI 入口 | 按复合身份独立读取当前 owner、URI、区块 | 自建同名假标准合约声称已兼容 |
| 官方 ABI 与部署信息 | 复制最少需要的接口、保留许可证和源 commit | 从博客复制地址直接开主网写入 |
| 8004scan candidates | 分页找公开身份，选少量候选，再回链验证 | 将站内评分改名作为自研测评分数 |
| registration file / services | 固定原文、URI内容摘要、服务信息、认证要求 | 信任元数据自带任意 RPC/URL/工具指令 |
| agentWallet | 记录为标准定义的收款钱包字段 | 自动推断它就是执行钱包、全历史都可归因 |
| 标准 feedback/validation 能力 | P1 把自研报告作为外部可引用结果，另行定义映射 | P0 再实现评论、质押、全网排名、仲裁 |
| best-practices 的可用性/成功率/延迟 | 参考指标口径、注明来源 | 把在线率或时延监测本身当主要创新 |

## 3. 模块与输出
`Scan8004DiscoverySource` 仅返回 CandidatePage；`Erc8004RegistryReader` 仅返回 SnapshotCandidate。两者不能写 assertions、scores、verified bindings。
Discovery记录 `source_url/request_params/fetched_at/response_blob_hash/source_version`；保留 registry_address，不能只用 tokenId 合并多链、多注册表对象。
读取链上时保存 `chain_id/block_number/block_hash/registry/owner/uri`，将相同区块下的查询作为快照；不一致或RPC缺数据标为unknown。
ERC-8004、执行链、报告锚定链分开配置；共享测试网上注册，不意味着可以在该链随意给 Agent 发送写任务。

## 4. 上游锁定流程（M0-07 准备，M4-01 live）
1. 读取官方仓库默认分支与当前提交；本次网页显示 master，但不要长期硬编码分支名。
2. 选择实际使用 commit，保存仓库URL、commit、获取时间、license、ABI原字节SHA-256；实现接口所依据EIP网页另保存快照摘要。
3. 在 `third_party/erc8004/` 只放必要ABI/许可/说明；不能假设代码仓库与EIP文字在任意时点完全一致。
4. `upstream-lock.json` 必须填真实40位commit和实际hash。示例文件的null不是可运行锁，live启动发现null必须报 `UPSTREAM_NOT_PINNED`。
5. 配置链与注册合约后，通过受信RPC核对chainId、非空bytecode、部署资料、目标方法可读。若有代理，记录代理和实现信息及读取区块，不能把代理bytecode hash冒充固定业务实现。
6. 自动测试只用固定RPC响应/卡片fixture；live测试另带marker，缺网络/凭证显示BLOCKED，不覆盖离线测试结果。

本次仅从官方资料核对到 Ethereum Sepolia 的 Identity Registry 示例地址：
`0x8004A818BFB912233c491871b3d84c89A494BD9e`。[S02]
本包没有使用RPC实测该部署、没有固定其实际commit；示例外部配置因此保持disabled，不用于自动写链。不要从这里推导所有链相同地址都可用。

## 5. 8004scan 的最小导入流程
官方开发者入口给出基础地址 `https://api.8004scan.io/api/v1`，OpenAPI为 `https://api.8004scan.io/openapi.json`。[S03][S04]
先固定OpenAPI实际字节和hash，再生成或手写**只读且小范围**客户端。不要把整个网站克隆进仓库。

示例请求契约（不是已采集的数据）：
```text
GET /api/v1/agents?chain_id=11155111&is_testnet=true&is_registered=true&limit=10
GET /api/v1/agents/{chain_id}/{registry_address}/{token_id}
```
两段 `/{chain_id}/{token_id}` 的详情路由默认对应官方注册表场景；要保留自定义注册表身份时使用三段路由。以锁定后的OpenAPI为准。
分页使用cursor或offset其一，保持相同filters/sort，不混用；限制页数和候选总数。本次建议最多导入30个候选用于筛选，不做全网索引。
默认低速串行请求；服务端配额/429/Retry-After优先，不把网页当日配额写成永久保证。需要Key时从后端环境变量注入，不放浏览器/日志/公开包。
失败保留状态 `rate_limited/auth_required/service_unavailable/schema_changed`，不调用网页爬虫绕过限制，也不复制虚假“成功结果”。

## 6. 三层数据集，而不是一份混合排行榜
| 层 | 来源与规模目标 | 允许说明什么 | 不允许说明什么 |
|---|---|---|---|
| controlled-v1 | 本地A–H，固定异常模式和独立随机任务 | 预设反例覆盖、消融对比、复现 | 真实世界欺诈识别率 |
| public-snapshot-v1 | 先争取3个注册候选，至少1个真实链上快照 | 真实身份/描述接入与数据缺失情况 | 采集3个身份=完成3个Agent业务测评 |
| authorized-public-v1 | 提供方确认映射、绑定、grant后的小范围对象 | 特定时间/能力/接口上的实测结果 | 无授权把公开Agent当压力测试目标 |

公开Agent未必有本项目的 `anchor_record` 接口。输出“待适配/待授权/范围外”，不为获得演示分数擅自改接口、钱包绑定或业务含义。
元数据中的未支持协议保持字段和原因。A2A阶段只读Card，MCP只记录入口；完整调用adapter另设P1验收。
数据许可与API条件需按真实使用方式核查。公开可访问不等于可无限抓取或重新分发所有响应；仓库优先保留合法最小样本、来源和脱敏说明。

## 7. P1 写回标准声誉（不阻塞P0）
`FeedbackPublisher` 独立于评分器与自研EvaluationAnchor，默认关闭，要求负责人明确批准测试链/注册表/费用/发送账号。
固定 `giveFeedback` ABI版本、数值缩放、tag、URI/hash算法语义、评价者地址与撤回流程；本项目的keccak报告摘要不必等于标准接口要求的所有文件hash格式，必须按该版本规范分别计算。
只发布能追到报告的有限场景信号；不把Q解释成经过校准的概率。外部反馈作为背景，不能无条件回流给自研主评分，避免循环放大/刷评。
